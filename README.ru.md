# 🍳 WORD CHEF

**Готовь слова. Подавай блюда. Держи жар.**

> 🇬🇧 [English version](README.md) · 🇷🇺 Русская версия

Word Chef — оригинальная мультиплеерная веб-игра про кухню, где игроки-шефы
превращают буквы в блюда под давлением. Каждая подача считается
детерминированным серверным движком и **запечатывается как Prolepsis-исполнение**:
канонический дайджест, артефакты с адресацией по содержимому, чекпойнты, реплей
и криптографическая верификация. Читерство здесь не «не приветствуется» — ткацкий
станок физически не может выткать ложь.

> Буквы — ингредиенты. Слова — блюда. Заказы приходят от гостей с желаниями и
> секретами. Комбо и Жар множат всё — как и риск от Приправы.

---

## ✨ Чем игра отличается

| Механика | Что делает |
|---|---|
| **Вкусовые профили** | Каждое слово детерминированно получает вкус (сладкое / солёное / умами / кисленькое / насыщенное / классика). Гость *хочет* конкретный вкус — совпадение ×1.5, конфликт ×0.85. |
| **Mise en place (заготовки)** | Короткое слово (2–3 буквы) можно отложить как *заготовку*: немного очков, комбо не рвётся, и каждая заготовка даёт +10 % к следующему блюду. |
| **Секретное меню** | ~25 % заказов несут скрытую цель («5+ букв», «две гласные»…). Вскрой молча — получишь +50 %. |
| **Приправа** | Заряжает множитель ×2 — но следующая осечка сжигает комбо *и* жар. |
| **Золотые ингредиенты** | Редкие буквы (J/Q/X/Z) чеканят золотые звёзды: +15 с терпения, замена букв на подносе или буст ×1.5. |
| **Жар и Комбо** | Серии поднимают Жар (крупнее награды, сложнее заказы) и Комбо (до ×4). |
| **Кухни** | 7 стадий прогрессии (Уличная → Пекарня → Суши-бар → Космос → Кибер → Древняя → Полночная), каждая переписывает правила дома: рынки гласных, глитч-буквы, щиты комбо. |
| **Хаос-кухня** | Мультиплеерный саботаж: украсть ингредиенты, сжечь таймеры, буря специй, обмен подносов, двойные заказы — полностью детерминированно, без pay-to-win. |
| **Таймер пережога** | Быстрые блюда — *аль денте* (×1.2); опоздавшие пережарены (×0.9). Единственные часы — серверные. |

Режимы: **СОЛО** · **БЫСТРАЯ ГОТОВКА** (2–8 шефов, одинаковые заказы) ·
**ХАОС-КУХНЯ** (разные заказы + хаос-события + 🔔 колокол).

## 🎮 Кампания и контент

Помимо мультиплеера в игре есть кампания в традиции «Повара Слов»: буквенное
колесо, крестословная доска, банка бонусных слов, монеты, подсказки и карта кухонь.

* **48 блюд** — от салата и борща до рамена, паэльи и чизкейка; у каждого своя
  картинка и короткая рецептурная заметка.
* **7 кухонь** с собственными гостями (Марко, Бабушка Зита, Юки, Космо-шеф,
  Нейро, Мудрец, Кот Борис) и репликами — вступительными и по ходу готовки.
* **Уровни** генерируются детерминированно из буквенного пула: Python-движок и
  его TypeScript-зеркало обязаны совпадать (это проверяется тестом, см. ниже).

Оформление: единый набор арта в «пластилиновом» 3D-стиле (блюда, гости, кухни,
медальоны, UI-иконки, баннеры). Соглашения по ассетам, промпт-скелет стиля и
бюджет бандла — в [`docs/art-pipeline.md`](docs/ru/art-pipeline.md).

## 🏗 Архитектура

```
┌────────────────────┐   интенты (WS/REST)   ┌───────────────────────────────┐
│  Next.js фронтенд  │ ────────────────────► │  FastAPI бэкенд (авторитетный)│
│  (TS, mobile-first)│ ◄──────────────────── │  · оркестрация матчей         │
└────────────────────┘   события / виды      │  · SQLite-персистентность      │
                                             │  · WebSocket-лента             │
                                             └──────────────┬────────────────┘
                                                            │ каждая значимая операция
                                                            ▼
                                             ┌───────────────────────────────┐
                                             │ Prolepsis Agent Platform v1   │
                                             │ (v0.39.0 · WEAVE / JACQUARD)  │
                                             │  · асинхронные исполнения     │
                                             │  · Jacquard-паттерны (YAML)   │
                                             │  · веверы пересчитывают       │
                                             │  · CAS-артефакты · чекпойнты  │
                                             │  · replay · verify · audit    │
                                             └───────────────────────────────┘
```

* `game/wordchef_game` — чистое детерминированное ядро игры (RNG, словарь,
  заказы, скоринг, кухни, хаос, движок). Ноль IO. Один seed ⇒ один матч.
* `prolepsis/wordchef_prolepsis` — мост исполнения: 10 игровых операций →
  Prolepsis-исполнения, чтение CAS, верификация, аудит.
* `prolepsis/patterns/wordchef/` — **Jacquard v0.4 YAML-паттерны** (dish, order,
  round, match, bonus/chaos, leaderboard, verification).
* `prolepsis/vendor/` — Prolepsis v0.39.0 (закреплён, 2 задокументированных
  микропатча, см. `prolepsis/vendor/PATCHES.md`).
* `backend/` — FastAPI + SQLite + WebSocket.
* `frontend/` — Next.js 14, статический экспорт (TypeScript).
* `tests/` — юниты · правила игры · API · prolepsis · детерминизм · мультиплеер ·
  анти-чит · персистентность · фронтенд-смоук · целостность арта.

### Поток данных одного блюда

```
интент клиента {word}  →  engine.score_dish (чистая функция)  →  Prolepsis-исполнение
   →  селвиджи Jacquard проверяют инварианты (score ≥ 0, combo ≥ 0 …)
   →  вевер ПЕРЕСЧИТЫВАЕТ блюдо и сравнивает каждое заявленное поле
   →  отказ? → исполнение FAILED → состояние игры не двигается
   →  ок? → DishReceipt + ScoreSheet втканы в CAS → дайджест → чекпойнт
   →  состояние сохранено → рассылка по WebSocket
```

## 🚀 Локальный запуск

```bash
# 1 · зависимости бэкенда
pip install fastapi "uvicorn[standard]" pydantic

# 2 · фронтенд (в репозитории уже собран; пересобирайте после правок UI)
cd frontend && npm install && npm run build && cd ..

# 3 · запуск кухни (API + игра на одном порту)
PYTHONPATH=backend:game:prolepsis:prolepsis/vendor \
  python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# открыть http://localhost:8000
```

## 🔌 Интеграция с Prolepsis

Prolepsis v0.39.0 (Agent Platform v1) — это **слой исполнения и рантайма**,
а не декорация:

| Игровая операция | Jacquard-паттерн | Событие(я) | Артефакт(ы) |
|---|---|---|---|
| 1 · создание матча | `match.yaml` | `MATCH_CREATE` | `MatchCloth` |
| 2 · старт раунда | `round.yaml` | `ROUND_START` | `RoundTicket` |
| 3 · генерация заказа | `order.yaml` | `ORDER_GENERATE` | `OrderTicket` |
| 4 · ответ игрока | `dish.yaml` | `DISH_SUBMIT` | `DishReceipt` |
| 5 · начисление очков | `dish.yaml` | `SCORE_AWARD` | `ScoreSheet` |
| 6 · бонусы / хаос | `bonus.yaml` | `BONUS_APPLY`, `CHAOS_EVENT` | `BonusCoupon`, `ChaosNotice` |
| 7 · конец раунда | `round.yaml` | `ROUND_END` | `RoundSummary` |
| 8 · фиксация результата | `match.yaml` | `MATCH_FINISH` | `MatchSignOff` |
| 9 · таблица лидеров | `leaderboard.yaml` | `LEADERBOARD_UPDATE/COMMIT` | `LeaderboardSheet`, `LeaderboardSeal` |
| 10 · реплей/верификация | `verify.yaml` | `MATCH_VERIFIED` | `VerificationReport` |

(4 и 5 — одно атомарное полотно: блюдо и его счёт никогда не разделяются.)

Гарантии рантайма, проверяемые `scripts/acceptance_prolepsis.py` (29 проверок):
`health` · `ready` · `version` (в процессе **и** по HTTP `agent-serve`),
асинхронные исполнения, артефакты CAS, чекпойнты, реплей, верификация
(`recorded digest == recomputed digest`), выживание после рестарта, аудит-события,
идемпотентность по request-id.

Каждое значимое исполнение даёт: `execution_id · digest · artifact_refs ·
checkpoint_id · verified=true`.

## 🎲 Правила игры (кратко)

* **Раунд** закрывается, когда каждый шеф подал 3 блюда (или пропустил).
* **Блюдо** — реальное слово из словаря, собранное из выданного сервером
  подноса, и оно должно удовлетворять текущему **заказу** (длина, буква, тема,
  серия, скорость).
* Счёт = `quality(word) × combo × heat × spice × kitchen × flavor × speed ×
  prep × secret` — считается один раз на сервере в `game/wordchef_game/scoring.py`
  и **пересчитывается внутри Prolepsis**.
* Ошибки сбрасывают Комбо (Древняя кухня щитит 1 уровень) и остужают Жар
  (Полночная кухня не остывает).
* Полные правила: [`docs/game-rules.md`](docs/ru/game-rules.md).

## 🔒 Безопасность и анти-чит

* **Сервер — источник правды.** Клиент отправляет `intent + word`. Счёт, комбо,
  жар, таймеры, награды, инвентарь и позиции в таблице считаются на сервере.
  Клиентские поля `score`/`combo`/`golden` игнорируются.
* **Станок отказывается лгать.** Заявленные блюда *пересчитываются* вевером;
  любое расхождение ⇒ `constraint_broken` ⇒ исполнение `FAILED` ⇒ состояние игры
  не двигается. Доказано тестами в `tests/anti_cheat/`.
* **Селвиджи** (Jacquard-охранники) проверяют структурные инварианты
  (`score ≥ 0`, `combo ≥ 0`, `position ≥ 1`, `valid ∈ {0,1}` …) до того, как
  соткётся артефакт.
* **Канонические дайджесты** связывают (вход → результат); реплей и верификация
  обнаруживают любую подмену конверта.
* **Идемпотентные request-id** — повторные запросы не применяются дважды.
* **Политика capability** — игровой движок держит только `weave.artifact`;
  всё остальное отказывает по принципу fail-closed.
* **Секреты**: секретов нет в IR и артефактах; матчмейкинг по match id; API
  никогда не доверяет клиентским часам. Разворачивайте за TLS
  (см. [`docs/deployment.md`](docs/ru/deployment.md)).
