# Word Chef · арт и контент-пайплайн

> 🇬🇧 English original: [`../art-pipeline.md`](../art-pipeline.md)

Всё, что нужно знать будущему коммиту в духе «добавить ещё блюд / кухонь /
гостей». Охват: UI кампании (`frontend/components/ChefGame.tsx`), движок уровней
(`game/wordchef_game/levels.py` + его TS-зеркало) и набор ассетов в
`frontend/public/img/`.

---

## 1 · Конвенции ассетов

Весь арт — одно «пластилиновое» 3D-семейство: крупные мягкие формы, глянцевая
пластилиновая фактура, тёплая палитра, **бесшовный кремовый фон**
(`#f6e7cd`-около), мягкий студийный свет, аккуратная контактная тень, без текста.

| Вид | Файлы | Отгружаемый холст | Размер на экране |
|---|---|---|---|
| Блюда | `dish_<латиница>.webp` | 512 × 512 (≤ 60 КБ) | 92 px (`.wc-dish-img`), 140 px (`.big-img`) |
| Гости | `guest_<кухня>.webp` | 512 × 512 (≤ 60 КБ) | 52 px круглый (`.wc-guest`) |
| Кухни | `kitchen_<id>.webp` | 512 × 512 (≤ 60 КБ) | 48 px (карта) |
| UI-иконки | `ui_<имя>.webp` | 256 × 256 | 18–54 px инлайн |
| Медальоны | `ach_{gold,silver,bronze}.webp` | 256 × 256 | 34–56 px |
| Баннеры | `hero.webp` 820 × 410, `splash.webp` 349 × 620, остальные 1:1–2:1 | — | CSS `background-size: cover` |

**Баннеры — отдельное визуальное семейство.** Если блюда и персонажи — «пластилин»,
то баннеры (`mode_*`, `lobby_banner`, `results_banner`, `howto`, `hero`,
`splash`, `grandtour`, `grand_map`, `recipe_book`, `celebrate`) — детальная
2D-живопись в тёплой палитре: тёмное дерево, латунные лампы, пар, летящие
билеты. Новый баннер должен попадать в это семейство, а не в пластилиновое:
промпт начинается с `Vibrant 2D cartoon game banner: …`, заканчивается
`wide banner composition 2:1, no text, no lettering, no watermark`.

Скелет промпта для блюда (подставьте только субъект, остальное сохраняйте):

```
<СУБЪЕКТ>, served on a simple pale ceramic plate, top-down three-quarter view —
3D clay/CGI render in a mobile game icon style: chunky soft cartoon shapes,
glossy plasticine texture, warm cream-beige seamless background, soft studio
lighting, gentle drop shadow, centered composition, square 1:1, appetizing,
no text, no watermark, no hands
```

Для иконок (без тарелки) хвост тот же, но с `<СУБЪЕКТ>, single object isolated
on a plain warm cream-beige background — …`.

## 2 · Как подключить новое блюдо (4 файла, по порядку)

1. `game/wordchef_game/levels.py` → добавить `{"emoji": "…", "name": "…"}` в
   конец `DISHES`.
2. `frontend/lib/levels.ts` → добавить **ту же запись на ту же позицию** в
   свой `DISHES`. Порядок — часть контракта между двумя движками.
3. `frontend/components/ChefGame.tsx` → добавить `"<Название>":
   "img/dish_<латиница>.webp"` в `DISH_ART` (fallback — салат).
4. Положить арт в `frontend/public/img/`, затем прогнать инструменты —
   нормализатор приведёт холст к отгружаемому и подберёт качество под бюджет,
   конвертер переведёт оставшийся JPEG в WebP:

   ```bash
   python3 scripts/to_webp.py                # если пришёл JPEG
   python3 scripts/to_webp.py --write
   python3 scripts/normalize_art.py          # что будет сделано
   python3 scripts/normalize_art.py --write  # применить
   ```

   Никогда не коммитьте сырой вывод генератора 1024² — см. §5.

5. Добавить строку рецепта в `frontend/lib/dishNotes.ts`. Тест целостности
   этого требует: блюдо без рецепта валит набор.

Блюдо ↔ уровень отображается детерминированно:

```python
dish = DISHES[(level_no // 10) % len(DISHES)]
```

Поэтому добавление блюд перестраивает уровни начиная с `10 · len(DISHES)` —
это изменение контента, а не баг. Уровни 1–9 («Салат») не двигаются никогда.

## 3 · Гости и реплики

`GUEST_ART` (портрет + ник), `GUEST_LINES` (3 вступительные фразы на кухню) и
`GUEST_PROGRESS` (по 2 реплики на 1/3 и 2/3 доски) живут в `ChefGame.tsx`.
Строка для уровня выбирается детерминированно:

```ts
lines[(max(1, levelNo) - 1) % lines.length]
```

то есть реплей того же уровня читается идентично. Добавляя кухню: заведите её в
`KITCHENS` (`levels.py` **и** `levels.ts`), в `KITCHEN_RU`, в `GUEST_ART`,
в `GUEST_LINES` и `GUEST_PROGRESS`, и положите `kitchen_<id>.webp` +
`guest_<id>.webp`.

## 4 · Золотой ингредиент

`ui_gold_tile.webp` — пустая золотая плитка с фаской, вырезанная из первого
рендера `splash`. В UI кампании она подаётся как инлайновый `background-image`
на выбранную букву колеса — см. рендер `wc-tile` в `ChefGame.tsx`. Мультиплеер
держит собственную экономику ⭐ (`me.golden`); плитка — чисто визуальный сигнал
и на скоринг не влияет.

## 5 · Бюджет бандла (жёсткий тест)

`tests/frontend/test_smoke.py::TestFrontendBuild::test_bundle_stays_small`
падает, если весь статический экспорт превышает **4 МБ** — mobile-first, и
Android-сборка вшивает `frontend/out` в APK-ассеты.

| Дата | Бандл | Дельта |
|---|---|---|
| до `0f3558f` | ~3.5 МБ | — |
| после арта на 22 блюда (`0f3558f`) | 4.2 МБ (1024²) | **перебор** |
| после нормализации к 620² + 28 блюд + иконки | 3.59 МБ | запас 417 КБ |
| после 38 блюд + UI-иконки + RU-сборка | 3.47 МБ | запас 538 КБ |
| после 48 блюд + WebP-миграции | 2.64 МБ | запас 1393 КБ |
| после 54 блюд + новых баннеров | 2.69 МБ | запас 1338 КБ |
| после оформления игрового процесса (11 UI-ассетов) | 2.93 МБ | запас 1093 КБ |

Правила:

* не коммитить 1024² JPEG — UI показывает максимум 140 px;
* один ассет блюда ≈ 15–55 КБ;
* бюджеты живут в `scripts/normalize_art.py` (`RULES`), а не в чьей-то голове.

WebP-миграция выполнена (`scripts/to_webp.py`): полезная нагрузка картинок
упала с 3.50 МБ до ~1.5 МБ (−42 % на момент миграции, −55 % на следующих
партиях) без видимой разницы на этих размерах отображения. Если запас снова
сожмётся, следующие рычаги: 384² для блюд (всё ещё выше 140 px) и баннеры
шириной 640 вместо 820.

## 🎮 Оформление основного процесса

Игровой процесс собран из сгенерированного арта, а не из градиентов:

| Место в интерфейсе | Ассет | Как применён |
|---|---|---|
| Фон кампании | `ui_wood_table.webp` | деревянный стол под тёплой заливкой (`html, body`) |
| Доска кроссворда | `ui_board_surface.webp` | разделочная доска, та же, что в арте блюд |
| Клетки доски | — | «гнёзда»: тёмные углубления, `hot` — тёплый ободок внутри гнезда |
| Плитки колеса и букв | `ui_tile_wood.webp` | деревянные плитки; выбранная буква → `ui_gold_tile.webp` |
| Редкие буквы (J/Q/X/Z) | `ui_gold_tile.webp` | золотые ингредиенты сразу видны в подносе |
| Полоса прогресса | `ui_progress_strip.webp` | угольная лента с искрами |
| HUD мультиплеера | `ui_hud_plaque.webp` | латунная плашка на дереве (светлый текст) |
| Карточка заказа | `ui_ticket_paper.webp` | бумажный билет официанта |
| Главная кнопка | `ui_btn_plate.webp` | деревянная плашка (обрезана вплотную) |
| Поданное блюдо | `ui_plate_round.webp` | пустая тарелка под блюдом |
| Фон игрового экрана | `bg_game_kitchen.webp` | ночная кухня с боке вместо размытой заливки |

Плитки и плашки используют `background-blend-mode: multiply` — светлое дерево
из генератора темнеет до игрового тона, а текст остаётся контрастным.

### Ловушка при сборке APK: пути внутри CSS

`url(/img/…)` в CSS разрешается относительно **самого файла стилей**, а не
документа. Под `file://` в WebView это указывало бы в корень файловой системы.
`scripts/build_android.sh` переписывает такие ссылки в правильное число `../`
по глубине файла (для `next/static/css/` — три уровня). Проверено на собранном
APK: все девять CSS-ссылок резолвятся внутри `assets/www`.

### Проверено браузером

Экраны снимались headless-браузером (Playwright) на живом сервере: фон, доска,
золотые плитки по тапу, HUD, билет заказа, деревянные кнопки. По ходу проверки
нашлись и исправлены два реальных дефекта:

* плитки мультиплеера имели класс `letter`, а CSS-правило было написано на
  `.letters .tile` — правило не срабатывало (буквы оставались белыми квадратами);
* **тап по букве не работал вообще**: `pointerup` очищал выбор, если жест не
  прошёл по двум и более плиткам, то есть подсказка «свайпни или тапни буквы»
  врала. Теперь одиночный тап набирает слово, свайп по двум и более плиткам
  готовит блюдо сразу, а отправить набранное можно кнопкой ✅.

## 6 · Android-сборка

```bash
TOOLS_DIR=~/.cache/wc-tools bash scripts/bootstrap_android_tools.sh   # JDK 17 + Gradle 8.7 + SDK 34
JAVA_HOME=… ANDROID_HOME=… GRADLE=…/gradle-8.7/bin/gradle bash scripts/build_android.sh
```

Проверено: `assembleRelease` собирает подписанный APK за ~50 с; внутри
`assets/www` — 93 WebP, ни одного JPEG, `_next` переименован в `next`,
ссылки относительные (`./next/…`, `img/…`), подпись v2 валидна
(`apksigner verify`).

Важно для `file://`: AAPT пропускает каталоги ассетов, начинающиеся с `_`,
поэтому скрипт переименовывает `_next` → `next` и делает пути относительными —
без этого WebView в Android не загрузит ни JS, ни картинки. Если добавите новый
каталог с подчёркиванием в начале, допишите его в тот же шаг перезаписи.

## 7 · Фикстуры уровней и паритет

```bash
python3 scripts/regen_levels_golden.py            # показать расхождения (без записи)
python3 scripts/regen_levels_golden.py --write    # зафиксировать новый эталон
python3 scripts/check_levels_parity.py            # скомпилировать TS-зеркало и сравнить
```

`check_levels_parity.py` компилирует `frontend/lib/levels.ts` собственным
TypeScript репозитория и сравнивает с Python-движком для каждого уровня из
фикстуры, печатая первое разошедшееся поле при провале. Пользуйтесь им: тихое
расхождение двух генераторов означает, что клиент и сервер по-разному видят
доску, — ровно тот класс багов, который эта игра построена исключать.
