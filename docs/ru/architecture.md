# Архитектура

> 🇬🇧 English original: [`../architecture.md`](../architecture.md)

## Компоненты

| Слой | Путь | Ответственность |
|---|---|---|
| Ядро игры | `game/wordchef_game/` | Чистые детерминированные правила: RNG (SplitMix64), словарь, подносы, заказы, скоринг, кухни, хаос, автомат состояний матча. Без IO, без чтения часов — кроме явно переданного `now`. |
| Мост исполнения | `prolepsis/wordchef_prolepsis/` | `WordChefRuntime`: Agent Gateway + веверы-обработчики + CAS + маппинг операций. Каждая значимая игровая операция становится исполнением. |
| Jacquard-паттерны | `prolepsis/patterns/wordchef/` | Декларативные воркфлоу (dish, order, round, match, bonus, leaderboard, verify) с селвиджами (охранниками) и шаблонами утка́ (квитанции). |
| Бэкенд | `backend/app/` | FastAPI: REST + WebSocket + статический фронтенд. Оркестрация матчей, персистентность SQLite, шина событий. |
| Фронтенд | `frontend/` | Next.js 14, статический экспорт, TypeScript, mobile-first. Отправляет интенты, рисует состояние. |

## Контракт детерминизма

```
матч = f(seed, последовательность интентов, метки времени от СЕРВЕРНЫХ часов)
```

* Потоки RNG производные: `sha256(master_seed ‖ context)` → SplitMix64.
* Скоринг — одна чистая функция (`scoring.score_dish`).
* Завершённый матч воспроизводится байт-в-байт из `(seed, лог интентов)` —
  `POST /api/matches/{id}/verify` прогоняет его заново и сравнивает.

## Поток исполнения (пример с блюдом)

1. `POST /api/matches/{id}/intent {action: SUBMIT_DISH, word}`
2. `engine.apply_intent` — валидация против словаря + подноса + заказа,
   вычисление `DishResult` (чистая функция).
3. `ops.op_submit_dish` формирует факты-заявки `DISH_SUBMIT` + `SCORE_AWARD`.
4. `WordChefRuntime.execute_op` → `AgentGateway.execute` (Prolepsis):
   * селвиджи проверяют инварианты (`score_delta ≥ 0`, `valid ≤ 1` …);
   * вевер `wordchef` **пересчитывает** блюдо из заявленных входов и
     сравнивает каждое поле — расхождение ⇒ `IRError(constraint_broken)` ⇒
     узел `failed` ⇒ исполнение `FAILED`;
   * при успехе уто́к (квитанция) рендерится и коммитится в CAS;
   * канонический дайджест + ссылки на артефакты + чекпойнт записываются.
5. Если исполнение не `COMPLETED`, сервис бросает исключение — **состояние
   игры не двигается** (интент остаётся в логе для аудита).
6. Снимок состояния сохраняется в SQLite; событие рассылается в WS-ленту.

## Персистентность

| Хранилище | Содержимое | Расположение |
|---|---|---|
| SQLite | игроки, матчи + снимки состояний, лог интентов, индекс исполнений, таблица лидеров | `data/wordchef.db` |
| JSON-хранилище Prolepsis | конверты исполнений (события, дайджесты, чекпойнты, рантайм-лог) | `data/prolepsis/executions/` |
| Persistent CAS | полезные нагрузки артефактов (адресация по содержимому, `sha256:…`) | `data/prolepsis/cas/` |

Все три переживают рестарт; `tests/persistence/` доказывает, что блэкаут
посреди матча ничего не теряет и игра продолжается.

## Параллелизм

`RLock` на матч сериализует обработку интентов; асинхронные исполнения
Prolepsis используют пул воркеров (`prepare`/`execute_queued`); WebSocket-ленты
работают без поллинга (asyncio-очереди с keepalive-пингами).
